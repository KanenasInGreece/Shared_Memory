Semantic & Contextual Memory Convergence

Architectural Analysis: Double-Anchoring (Site A) vs. Tier 3 Distillation (Site B)

1. Executive Summary: The "Two-Hemisphere" Brain

Modern agentic memory requires a converged substrate that mimics human cognition by separating "Intuition" from "Logic."

  • Semantic Layer (PostgreSQL/LanceDB): The Intuition Hemisphere. Stores document chunks and high-dimensional vectors (BGE-M3 1024-dim). Excels at Semantic Proximity.
  • Relational Layer (Neo4j): The Logical Hemisphere. Stores explicit entities and functional relationships. Excels at Deterministic Multi-hop Reasoning.

2. Comparative Analysis: Site A vs. Tier 3 (Site B)

The Tier 3 Experiment: Distillation Logic

Our Tier 3 project (OpenClaw) demonstrates a sophisticated inversion of the standard RAG pipeline. Instead of expanding a hit at runtime, it uses Index-Time Distillation.

Feature Current (Site A) Tier 3 (Site B)
Retrieval Pattern Search-Time Expansion Build-Time Distillation
Sync Logic Double-Anchoring (Forward Sync) Knowledge Compression (Back-Distillation)
High-Speed Memory PostgreSQL/pgvector LanceDB (Distilled Narratives)

"Tier 3 doesn't just store what happened; it compresses logic into a high-performance vector format, allowing agents to retrieve a full 'Why-To' context in a single shot."

4. Convergence Achievement: Implementing the Hive-Mind

1. Automated Back-Link: We have successfully implemented a system that not only syncs Forward (Postgres → Neo4j) but also distills graph clusters back into the semantic layer.

2. Consolidation Sleep Cycle: The consolidation_loop.py acts as the background "Sleep Cycle," resolidifying fragmented facts into hierarchical summary nodes periodically.

3. Provenance Capture: We now store full Reasoning Traces in Neo4j, ensuring that the Session Logic (the 'Why') is preserved alongside the technical facts.

5. Proposed Unified Architecture (Implemented)

Direction: The "Hive-Mind" Consolidation Loop

For the formal architectural decision record, see ADR.md.

  1. Pulse: Postgres LISTEN/NOTIFY emits a pg_id on every insert (The Heartbeat).
  2. Wait: A Python daemon resets a Sleep Timer to ensure consolidation only happens during system idle time.
  3. Evaluate: Using the pg_id as an entry point, the daemon evaluates Localized Density of unflagged Facts in Neo4j.
  4. Distill: High-density clusters are summarized by an LLM and back-vectorized into community_summaries.
  5. Flag: Processed facts are marked consolidated=true in Neo4j to manage state and prevent recursion.
