# vector-skill.py's only third-party imports are fastmcp and httpx (verified,
# W7 S6) — the connector talks to the gateway over HTTP, it never touches
# Postgres/Neo4j directly, so this is deliberately narrower than
# requirements.txt or requirements-gateway.txt.
#
# ⚠ THIS PAIR IS NOT ON THE SPAWN PATH — it is the HASHED AUDIT ARTEFACT and
# the SOURCE OF TRUTH the connector's own pins are checked against. The
# documented spawn line is `uv run --no-project mcp/vector-skill.py`: the
# connector carries PEP 723 inline metadata naming fastmcp and httpx by exact
# version, because `--with-requirements` resolves this file relative to
# whatever directory the MCP host happens to spawn from (measured: `error:
# File not found`, and a hijack surface for anyone who can plant a file of
# that name there). `tests/test_mcp_spawn_lines_pinned.py` asserts that the
# two inline versions equal the versions pinned in requirements-mcp.lock, so
# editing one without the other turns the suite red.
#
# Regenerate the pinned lock after editing (same form as requirements-gateway.lock):
#   uv pip compile requirements-mcp.txt -o requirements-mcp.lock --generate-hashes
# then re-apply the three-line note at the top of the lock (uv rewrites the
# whole file) and re-check the inline block in mcp/vector-skill.py.
